# 实战经验与踩坑录（lessons-learned）

> 来源：mdshow 多轮真实构建——五套主题开发、27 页高密度课件复刻（南大《生成式软件工程》
> 开场白 24 图逐页转录）、GitHub 发布运维。每条都是**真实翻过车**的问题，按
> 「症状 → 根因 → 解法 → 规则」记录。做页数多、密度高的演示文稿前先通读一遍。

## A. 排版与渲染

### A1. 数学公式"整体斜体"的刻意感
- **症状**：公式渲染出来像"把英文字母斜了一遍/加粗了一遍"，函数名、数字、变量全倒，观感刻意。
- **根因**：图省事把 `.math` 容器整体 `font-style: italic`——违背数学排版惯例。
- **解法**：按 ISO 80000 / LaTeX 惯例**按词性区分**：单字母变量（x, n, c, s…）斜体
  `<var>`；函数名与多字母标识符（Pr, concat, Base64…）、数字、运算符一律正体。
  引擎在 `render_math()` 里自动完成词性识别（单字母→var，多字母不动）。
- **规则**：容器绝不整体 italic；衬线字体（Times/Georgia）+ 字号 +5% 补偿 serif 偏小
  的 x-height，与 sans 正文视觉等大。

### A2. 数学变量误用 `<i>`：与中文着重号冲突
- **症状**：数学变量若用 `<i>`，在中文主题里会跟着着重号（text-emphasis 圆点）一起渲染。
- **根因**：中文没有真斜体，主题把 `em/i` 统一映射为着重号；`<i>` 语义被中文排版征用。
- **解法**：数学变量一律用 `<var>`（HTML 语义就是"变量"，默认 italic，且不碰着重号选择器）。
- **规则**：数学内部标签只用 `var/sub/sup`，禁用 `i/em/b`。

### A3. 条件竖线 `∣`（U+2223）缺字形，渲染像斜杠
- **症状**：`\mid` 映射为 U+2223 后，Times/Georgia 无此字形，浏览器回退渲染后观感近似"/"。
- **解法**：`\mid` 映射为普通竖线 `|`，并在紧贴侧补薄空格（U+2009）留气口；
  两侧已有空格则不补。
- **规则**：数学符号选字形时优先"常用字体必有的"，花哨 Unicode 字符先在小截图里目检。

### A4. LaTeX 源码裸露（jyy 原版 tu13 翻车案例）
- **症状**：原版课件直接把 `$P(x_{1:n}\mid c)=\prod_i...` 印在幻灯片上，观众看到的是源码。
- **根因**：作者没渲染（或渲染失败后放弃），裸码比不写更伤专业性。
- **解法**：轻量 TeX 渲染——常用命令映射 Unicode + `_{}`/`^{}` 上下标 + `\sqrt{}`，
  保证"写出来的公式一定能落到可读的字形"。
- **规则**：宁可少写公式，不可裸奔源码；构建后对含 `$` 的页必须截图目检。
- **复发变体（2026-09，全格式测试稿踩中）**：命令表覆盖不足同样裸露——
  测试稿写 `$O(n \log n)$`，`\log` 不在映射表，反斜杠原样印出。映射表是白名单，
  白名单的失效模式是"静默放过"，不会报错。**规则：新增/修改测试稿后，
  用"源稿命令集 × 映射表"做一次差集校验（两行正则的事），裸露命令要么补映射、要么换写法。**

### A5. inline-block 长卡换行，列表圆点漂移（jyy 原版同款 bug）
- **症状**：淡紫水印长卡折行后，`li::marker` 跳到第二行中间，版式眼花缭乱。
- **根因**：`display: inline-block` 元素的基线 = 内部最后一个行盒的基线，换行时基线错乱。
- **解法**：改 `display: inline` + `box-decoration-break: clone`——换行处每段都有完整底色。
- **规则**：行内装饰卡必须考虑折行；验证时专找"最长的那条"看折行表现。

### A6. 数学字体链漏掉中文兜底
- **症状**：公式字体设为纯西文 serif，公式旁的中文标点（，、：（））fallback 混乱。
- **解法**：字体链永远 `"Times New Roman", Georgia, "Noto Serif SC", serif`——
  中文兜底字体收尾。
- **规则**：任何 font-family 的最后一级必须是能接住全部实际字符的字体。

### A7. 行内公式从中间折断，观感割裂（用户反馈驱动，推翻本条旧结论）
- **症状**：长公式在行内被折成两截（white-space:normal），数学式断裂。
- **旧方案（已废弃）**：为防溢出放任断行，"宁可断行"——实测被用户否决：
  "一行数学公式尽量在一行，要么整行显示，要么另起一行居中"。
- **正解（三层递进）**：
  1. 行内公式 nowrap 整体不可分：行尾装不下时浏览器自动把整个公式挪到下一行
     （所在容器流不破坏，aigc 卡底色延续）；
  2. 比整个版心还宽的：runtime fixMath 测量后加挂 .math-block，升格为独立一行居中
     （行间公式观感）；极端超宽再以 max-width+overflow-x:auto 兑底；
  3. 独立成段的公式直接用 $$...$$ 展示块（天然独立居中）。
- **规则**：数学式是"不可分原子"；防溢出与防折断冲突时，让元素整体换行，
  而不是允许从内部断开；确需居中展示时由运行时测量升格，不靠手工预判。

### A8. 展示数学管线断接：剥掉定界符后规则永不命中（2026-09 用户报障）
- **症状**：行内 `$E=mc^2$` 渲染正常，独立成行的 `$$P(x_{1:n} \mid c)=\prod...$$`
  却整行裸奔源码——同页两种命运。
- **根因**：mathd 块分支误用 parse_inline——进入前 `$$` 定界符已被剥掉，
  而 parse_inline 里的数学规则按 `$` 定界匹配，永远无法命中；
  结果内容原样透传（esc 过但未渲染）。
- **解法**：mathd 分支直接 `render_math(esc(content))`——展示块语义就是纯数学，
  不需要走通用行内管线。
- **规则**：**存在性断言 ≠ 渲染正确性**——上轮验证只断言 `.math-display` 节点存在、
  未断言内容含 `<var>/<sub>`，三轮验证全绿依旧裸奔。对“渲染器”类代码，
  测试必须断言输出内容的质量（含什么标签/不含什么源码），不能只数节点。
- **规则二（块级语法独立通道）**：块级 token 一旦剥掉原始定界符（`$$`、`#`、`![...]`），
  就绝不能丢给行内解析器借道复用——必须显式调对应渲染函数（render_math/esc 等）；
  “块级触发后偷懒复用行内函数”是此类 bug 的固定温床。
- **排障指纹**：同页“行内正常 + 块级裸奔” = 两条渲染管线不等价，先比对管线，
  再逐级打印中间产物。

### A9. 容器内嵌彩底装饰，叠出“彩色阴影”观感（2026-09 用户反馈）
- **症状**：引用块（浅紫底 #F7F5FB）内嵌 aigc 水印卡（紫底紫字），
  两层紫色叠加，用户观感“文字彩色阴影”，且金句与正文同大不克制度。
- **根因**：装饰元素（.aigc）设计时只考虑了裸段落白底场景；放进带底色的容器后
  底色叠加没有重新目检——引言块本身已是“摘录”容器，再叠高亮等于双重标记。
- **解法（分层落定）**：
  1. **主题本体基线**（所有项目受益）：`blockquote.quote { font-size: .92em }`、
     内嵌 .aigc `background: transparent`（仅留 ✦ 与字重）；
  2. **项目 override**（按用户原话“不用加文字彩色阴影”）：内嵌 .aigc 再加
     `color: inherit` 收敛为墨色——容器语境 + ✦ 前缀已足够标识 AI 生成。
- **规则**：**彩底元素进入任何带底色容器时必须重新目检叠加效果**；
  aigc 视觉强度按容器语境分级（裸段落满强度，自带语义的容器降级）；
  嵌套降噪手法 = 去底色 + 颜色继承，保留语义标记（前缀/字重）不变。

### A10. 行内代码解析顺序：不冻结就会被其他规则吃掉
- **症状**：想在幻灯片里**展示**写法 `` `**x**` `` / `` `$y$` ``，渲染后星号被粗体规则吃掉、
  美元符被数学规则吃掉，代码里出现不该有的 `<b>`/`<var>`。
- **根因**：行内代码规则放在最后跑；标准 Markdown 中代码 span 是最先解析的，
  内容不参与后续任何规则。
- **解法**：parse_inline 里行内代码最先暂存（控制字符占位），链接/强调/数学/占位符
  全部跑完后最后还原。
- **规则**："展示语法"的载体只有行内代码；解析顺序 = 标准 Markdown 顺序
  （代码 → 图片 → 链接 → 强调 → 数学），图片规则必须排在链接前，
  否则 `![alt](src)` 的 `[alt](src)` 会被链接规则先吃掉感叹号。

### A11. 主题合成文件靠手工 `cat`，改一处忘一处（2026-09 双助手各踩一次）
- **症状**：nanda-gense 用 `theme-v2-nanda.css`（v2 本体 + override `cat` 而成），
  修改 `theme-nanda-override.css` 后直接重新构建，产物里的 CSS 还是旧的——因为
  buildall 只读 `theme-v2-nanda.css`，合成文件需要外部刷新。
- **根因**："追加覆盖法"需要合成步骤，但当前没有自动化。
- **解法**：在仓库里加一个简短的合成脚本（`examples/nanda-gense/build-theme.sh`
  `cat .../theme-v2-zitan.css theme-nanda-override.css > theme-v2-nanda.css`）；
  修改 override 后必须先跑一次合成，再构建产物；README 把这两步写明。
- **规则**：合成类文件的修改流程 = 改源片段 → 重合成 → 重构建。三步缺一
  看似没事，构建产物里藏的就是旧版本。

## B. 密度与分页

### B1. 高密度课件首轮大面积溢出（27 页复刻稿 8 页溢出）
- **症状**：忠实转录老师原稿后，8/27 页 scrollHeight 超出版心。
- **根因**：课堂课件信息密度天然超标（一页 6-9 个要点 × 长句 + 公式 + 引用卡）。
- **解法（处置顺序，先易后难）**：
  1. **token 级收紧**：行高取规范区间下限（1.5）、列表 gap 降一档（8px）、
     上下安全边距取下限（4.2%）——不碰字号梯度与对比度底线；
  2. 仍溢出才**拆页**：过密页一拆二，页标题加"（续）"，内容一字不删。
- **规则**：先收紧后拆页；拆页是最后手段，但该拆就拆，硬塞必然溢出。

### B2. "每页 ≤8 要点"在高密度原稿面前的执行
- **症状**：原版单页 10+ 要点，忠实转录即违反规范。
- **解法**：按小节语义拆成两页，原内容零删减；本次复刻拆了 3 页（原 24 图 → 成品 27 页）。
- **规则**：规范优先于"逐字复刻版面"，内容保真不等于版面保真。

### B3. 溢出检测必须脚本量化 + 按"分步末态"测
- **症状**：目检觉得"差不多"，上线后翻到某步溢出；或量了首态漏了末态。
- **根因**：分步幻灯片每点一下列表变长，最满状态才是检测对象；人眼对 5% 溢出不敏感。
- **解法**：Playwright 逐页 `scrollHeight vs clientHeight`；量之前先把所有
  `.fragment` 加 `visible`（末态）。
- **口径坑（2026-09 补）**：测量目标是**版心 `.slide-body`** 而非整页 `.slide`——
  整页口径会把封面装饰层算进去（假溢出 164px）；封面页没有 .slide-body，
  脚本需 null 保护跳过（与 verify_dialect 口径一致）。
- **规则**：交付前逐页脚本量化是最后一道闸，不可目检替代。

## C. 工具链与验证

### C1. Playwright hash 导航"假阴性"（多次复发，重点记）
- **症状**：`location.hash = '#/14'` 后截图/量高度，拿到的永远是第 1 页数据——
  溢出检测"全绿"但其实是同一页测了 27 遍。
- **根因**：runtime 只在**加载时**解析一次 `#/n`，不监听 hashchange；直接改 hash 不触发重渲染。
- **解法**：`goto(url#/n)` + `reload()` + 等 700ms；file URL 的 hash 是 `#/n` 不是 `/n` 也不是 `#n`。
- **变体（同日新坑）**：验证元素状态时用 `querySelectorAll(...)[last]` 取目标——
  文档序里 last 根本不是刚插入的合成元素，测了一个不相干的：测试断言必须指向明确目标，
  插桩前先打印选中元素的 textContent 确认身份。
- **规则**：对"只认加载时状态"的前端，一切导航 = 改地址 + 刷新；截图/断言前先确认页码
  （读 `.pageno`）与目标元素身份（读 textContent）。

### C2. 字面书写 `<span class="aigc">` 被白名单透传
- **症状**：写文档示例时把字面 aigc 标签写进讲稿，构建后示例文字变成了真水印。
- **根因**：白名单透传是特性（make-slides 产物直接可用），示例文字恰好踩中。
- **解法**：文档与示例一律用文字描述语法（"用 aigc 类的 span 标记"），不写字面标签。
- **规则**：透传类特性要意识到"写什么传什么"，示例与实做分离。

### C3. 构建告警 ≠ 构建失败
- **症状**：看到 `[warn] 图片占位符` 以为构建出错，白排查半天。
- **根因**：占位卡告警是**规范行为**——提醒补图，产物正常生成。
- **规则**：读告警文本再行动；区分 `[warn]`（预期提醒）与异常栈（真问题）。

### C4. raw.githubusercontent.com CDN 缓存延迟
- **症状**：推送后立刻打开 raw 链接，看到的还是旧内容，误判推送失败。
- **解法**：验证远端一律走 GitHub API（`/commits` 看最新提交、`/contents` base64 解码看内容）。
- **规则**：CDN 的"现在"不可信，仓库 API 的最新 commit 才是事实。

### C5. 凭记忆写外链必翻车（jyy.website 事故）
- **症状**：致谢里写了"jyy 主页：https://jyy.website/"，用户指正该链接根本不存在。
- **解法**：删除；外链写进任何交付物之前先 `curl -I` 验证可达。
- **规则**：宁可只写姓名，不写未验证的 URL。

### C6. 散文件交付 = 用户找不到文件
- **症状**：成品 HTML 放在深层目录里只报了路径，用户不知道去哪下载、怎么打开。
- **解法**：每次交付同步打一个 zip 包放到 download 根目录，内附"双击即开"的入口文件。
- **规则**：交付物以"用户拿到就能用"为完成标准，路径报备 ≠ 交付。

### C7. hash 页号是 1-based：0-based 传参全错位且不报错
- **症状**：验证脚本 `goto #/{i}`（i 从 0 起），以为在测第 3 页实际测的是第 2 页；
  溢出元组 `(页码, 像素)` 又被误读成 0-based 索引，对着错误的页调了一轮样式。
- **根因**：runtime 的 `#/N` 直接对应 `data-i`（1-based 页码）；`#/0` 不报错，
  静默回落，错位无从感知。
- **解法**：goto 前 `i+1`；溢出元组命名写清 `(page_no, px)`；断言前先断言页码对位。
- **规则**：跨层编号（0-based 循环变量 vs 1-based DOM 属性）在脚本入口处显式换算，
  不在断言里隐式补偿。

### C8. PIL + 可变字体：文字静默不渲染
- **症状**：用 `NotoSansSC[wght].ttf` 画示意图，`ImageDraw.text` 不报错但图上一个字都没有。
- **根因**：该 PIL/FreeType 组合对可变字体默认实例渲染异常；`set_variation_by_axes`
  也救不回。
- **解法**：改用静态字重文件（如 `NotoSerifSC-Medium.ttf`）。
- **规则**：生成图片后裁一块文字区域回读目检，再进入下一步。

## D. 工程纪律

### D1. 主题零改动原则：追加覆盖法
- **症状**：为单次项目改主题本体，回滚困难、污染其他项目。
- **解法**：新增 `*-override.css` 片段，合成时 append 在主题末尾（同名选择器后者生效）；
  原主题文件零改动、随时可弃。
- **例外**：当修正属于"全局正确性"而非"单项目特调"（如本次数学排版），直接改进主题本体，
  让所有后续项目受益——但要在注释里写明动机与日期。

### D2. 凭据安全：token 不落盘
- **症状**：token 写进 remote URL 后忘删，随 `.git/config` 泄漏。
- **解法**：临时 remote（origin-tmp）push 完立即 remove；token 只出现在当次命令行，
  不写入任何文件；交付后提醒用户撤销。

### D3. 分步数量的克制
- **症状**：125 个分步元素的高密度稿，逐条点击令人疲惫。
- **解法**：分步只给"有节奏价值"的要点；长引用块、图片卡随页直接显示（不计分步）；
  `{nf}` 显式关闭不需要的分步。
- **规则**：分步是演讲节奏工具，不是动画装饰。
